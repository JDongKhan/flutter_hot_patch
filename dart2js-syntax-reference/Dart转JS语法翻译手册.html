00给实现者的总则

这七条是后面所有规则的依据。实现时先落地这七条，再逐章补特判。

  1. 类型注解全部擦除，但泛型实参必须随尾参下发int、String?、List<T> 等标注不进入产物；但构造与方法的尾参对象必须携带 typeArguments（__ta，已有具名参数时复用 __o），运行时靠它完成 T == X、as T 与 provider 键控。擦注解不等于擦类型身份。
  2. 空安全没有运行时表示，但有运行时可观察行为! / ?. / ?[] / ?? 的语义必须靠改写保住三件事：接收者只求值一次、null 时短路、表达式返回值正确。
  3. 同名翻译优先，语义差异在运行时同名实现里对齐方法名默认原样下发；JS 侧缺同名成员时，运行时在具体内建原型上直接扩展同名方法（Array.prototype.clear / add / removeAt / fold）。同名已存在但参数 / 返回值 / 内部逻辑不一致时不覆盖原生：运行时扩展带下划线前缀的同名方法（_sort / _join / _setLength），生成器维护一张构建期映射表，主键是「接收者内建类型 + Dart 成员名」（如 (Array, sort) → _sort、(Array, join) → _join、(Array, length 写) → _setLength）。产物只在接收者静态类型可判定为该内建类型时按表改写成员名（Map 已纳入内建表：(Map, keys/values/entries) → _keys/_values/_entries）；自定义类 / 控制器等其它接收者上的同名方法一律原样，绝不改名。该表只覆盖「JS 内建已有同名但语义不一致」的固定清单，新增项必须同时改表与手册，不得按业务类名 / 白名单选择表行。统一用 Object.defineProperty、enumerable:false、存在性守卫，禁止挂 Object.prototype。
  4. Dart 只有 null，JS 有 null 与 undefined翻译器必须先定一个空值模型。推荐“宽空模型”：判空前先 __nn 归一（undefined → null），再用 == null（同时命中两者），合并统一用 ??。
  5. 编译期概念靠展开，不靠 JS 运行时特性mixin、extension、运算符重载、枚举都是编译期展开；判据只来自源码事实（类表、extends / with 链、import 归属、显式类型注解与项目类构造推断），不做运行时名字猜测，也不维护类型白名单（AGENTS §1 / §5）。
  6. 表达式位置和语句位置分开处理Dart 的赋值、复合赋值、自增都是有返回值的表达式；只按语句生成会静默丢值。
  7. undefined 一律归一为 nullJS 有 null 与 undefined 两个空值，Dart 只有一个。运行时提供归一函数 __nn(v)：v === undefined 返回 null，其他值原样返回（只归一，不抛错；非空断言 ! 是另一回事）。凡可能产出 undefined 的位置（Map 未命中、数组越界、可选链短路、缺省实参），判空与取用都先包 __nn：if (__nn(x) == null) …（== null 同时命中 null 与 undefined，禁止 === null）。只对「可能为空」的操作数包：字面量、构造、集合字面量、声明为非空类型（String / int / 项目类等）的字段 / 形参 / 局部变量不包；String? / dynamic / 类型不可判定（方法调用、下标、可选链）才包。项目现状：__nn 已实现（运行时 G.__nn，见 runtime_js.dart 的 _jsUiEnvVars）；判空 / 相等比较由 exprToJs 的 BinaryExpression 分支按操作数可空性（_mayBeNull）逐个决定是否包。
  8. 改写产物必须可验证每条改写规则都要能构造“null 分支 / 非 null 分支 / 求值次数”三个断言，任一不成立即视为实现错误。
实现者硬约束（先自查再动手·违反即视为未完成）
  1. 禁止自造产物形态与命名产物里出现的每一个非 Dart 名字（包装函数、类名、成员名、前缀、临时对象形态）都必须是本手册表格里登记过的。手册没写的一律不许实现；确需新增时，先补手册 + 让开发确认，再改代码。典型反例：__map(...) 包装字面量、__Map 类、{__proto__: Map.prototype, …}、__mapLength/__mapKeys 等按成员名造的自由函数。
  2. 成员翻译只有三种合法写法① 同名直译；② JS 已有同名但语义不同 → _ 前缀 + 构建期映射表（主键 = 接收者内建类型 + Dart 成员名）；③ JS 缺同名 → 运行时在具体内建原型上用 __defineProtoMember / __defineProtoGetter 两张表补同名。禁止为单个成员另写 helper 函数、禁止覆盖原生同名方法（除非手册明确登记，如 forEach 只在调用点交换参数、不覆盖）。
  3. 载体形态以本手册「JS 对应」列为准字面量的目标形态（List → []、Map → new Map([[k, v]])）不得擅自更改；改成包装函数 / 额外类 / 原型注入属于改协议，必须先确认、同次更新手册与架构文档。索引改写只允许手册登记的表项：仅 List/项目类/类型不可判定保持原生 a[i]，只有 Map 类型才按手册改写，禁止把辅助函数扩大到 List / 未知类型。
  4. 改前先查手册，改后回写手册动手前先定位本手册对应章节（含「翻译原则 / 现状 / 是否通过」）；改完必须同次更新对应行、CHANGELOG 与（涉及行为时）示例。手册未更新视为未完成；代码与手册不一致时以手册为准并立即收敛。
  5. 禁止“先实现再解释”无法在手册中找到依据的实现，一律停下先确认；不得用“内部原语 / 临时包装 / 为了兼容”作为绕过约束的理由。新增 __ 前缀原语同属产物形态，必须登记。

01翻译流水与输出约定

顺序不能乱：名字解析必须早于代码生成，空安全改写必须晚于类型提升分析。

流水线阶段

  • 解析：Dart AST，保留源位置，供报错与生成映射。
  • 类型与流分析（项目现状：不做）：项目用 parseString，没有 analyzer resolution / 流分析 / 类型提升；静态类型只来自显式注解与项目类构造推断，未知即不参与改写（不猜测）。
  • 名字解析（项目现状：类表 + 静态类型）：无符号解析；实例字段 / 方法按类表（含 extends 链）判定，extension 按源码归属改写，不做 import 顺序 / show-hide 冲突解析（冲突项构建期告警）。
  • 节点改写：空安全赋值、?? 括号、mixin 展开、extension 调用重写、枚举/record 结构替换。
  • 代码生成：ES2022 输出，括号按目标语言优先级重建。
  • 自检：求值次数、短路、返回值三类断言。

输出约定

ESM；单文件场景可用 IIFE 包裹
私有成员
_x → _x，原样保留下划线前缀；Dart 私有是编译期约定，运行时不强制
空值模型
宽空：判空 / 取用前先 __nn 归一（undefined → null，已实现），再 == null

为什么先做名字解析再做代码生成 extension 调用、mixin 成员复制、运算符重载都依赖“这个标识符到底指向谁”。先把符号绑定定下来，代码生成阶段才能只做局部改写，不用回头重扫全树。

function deepFreeze(v) {
  if (v instanceof Map) {
    for (const [k, x] of v) deepFreeze(x);
    Object.freeze(v);           // 仍可 set，语义上需要冻结代理
    return v;
  }
  if (v instanceof Set) {
    for (const x of v) deepFreeze(x);
    Object.freeze(v);
    return v;
  }
  if (v && typeof v === 'object') {
    for (const k of Object.keys(v)) deepFreeze(v[k]);
    Object.freeze(v);
  }
  return v;
}

  3. 返回值正确——表达式位置返回 null 或赋值结果，见第 03 章实测表。

10mixin

mixin 是编译期概念：声明按原文件路径产出独立类；with 在消费者产物里生成 application 类链，并用运行时 __mixinHard 复制成员。不能把 mixin 成员内联进最终类。

实现方案（唯一）

  1. mixin 声明按原文件路径产出独立类（纯 mixin 也是 export class，不能实例化；成员集合与静态成员保留）。
  2. class C extends S with M1, M2 在消费者产物里生成 intermediate application 类链：_C_S_M1 extends S、_C_S_M1_M2 extends _C_S_M1，最终 C 继承最后一层。
  3. 不带 super 的成员留在 mixin 类里，运行时 __mixinHard(app, M) 复制 mixin 原型上的自有成员；目标已有同名自有成员时不覆盖（因此后写的 mixin / 类自身声明优先）。
  4. 带 super 的方法在对应的 application 类里重新发射，原生 JS super 指向上一层（M2.log 的 super → _C_S_M1.log，M1.log 的 super → S.log）。
  5. mixin 实例字段不并进最终类，由对应 application 类的构造函数在 super(args) 之后初始化；顺序天然是 S → M1 → M2 → C。
  6. mixin class 同时按普通 class 产出（可实例化 / extends）；被 with 时走同一套 application 链，构造不参与混合。
  7. __mixinHard 调用统一下发在本模块全部类声明之后（class 有 TDZ，mixin 类可能声明得比 application 类晚）。

11extension

extension 是纯编译期概念：Dart 按接收者静态类型解析；本项目把成员装到目标类型原型上，调用点保持原样。

当前方案（本项目）

选择原型注册而不是编译期静态分派，原因是本项目只有源码级静态判定、没有完整类型推断：表达式的接收者类型经常不可判定，照搬静态分派会让大量调用退化成“无法改写”。原型注册让调用点保持 Dart 原样，且 registerExtension 的稳定 id 支持热更时先卸载再重注册。作为参照，dart2js 的做法是把扩展成员编译成模块内顶层函数、在调用点静态改写成函数调用（不碰原型），本项目未采用该形态。

  1. 成员（方法 / getter / setter / 运算符）编译成目标类型原型上的同名成员；声明所在的产物求值时执行一次 registerExtension(Target, { members }, { id })。
  2. 函数成员由严格模式函数承载，this 就是接收者（避免原始值装箱），与 Dart 的 this 语义一致。
  3. 调用点保持 Dart 原样：x.m() / x.m 直接落到 JS 成员读取。运算符无 JS 语法，声明侧改名 __op$add / __op$neg …，调用点按接收者静态类型改写成 receiver.__op$xxx(args)。
  4. 静态成员放在 extension 命名空间对象上（E.foo 原样访问）。
  5. 目标类型必须在 JS 侧有可挂载的原型（核心类型 / 运行时注入类 / 项目类）；Map / Object / dynamic / 宿主 widget 等没有单一实体原型的注册在构建期拒绝。

成员解析顺序（调用点重写必须遵守）

  1. 先找实例成员（含继承链）；找到就不走 extension。
  2. 再找当前作用域可见的 extension，按 import 顺序，受 show / hide 限制。
  3. 显式调用 E(x).m() 绕过前两步，直接绑定到 E。
  4. 同文件多个 extension 同名成员冲突：Dart 报编译错误，生成侧不应静默择一。
注册语义 扩展的 id 是稳定标识（<sourcePath>#<name>）：同 id 再注册时运行时会先卸载旧成员，热更不会重复叠加。目标类型没有实体原型（Map / Object / dynamic / 宿主 widget 包装类）时构建期直接拒绝，不产出必然无效的注册。

12集合方法差异

List 翻译成原生 Array；Map 字面量翻译成原生 JS Map（`m[k]` → get / set）。项目策略是同名直译 + 运行时按接收者类型补同名，禁止在翻译层把方法名改成 push / splice / filter / find / size / delete（AGENTS §5）；只有 JS 已有同名但语义不同（Array 的 sort/join/indexOf、Map 的 keys/values/entries）才按映射表加 _。

Stream：运行时自建，推送 + 拉取双形态

项目现状：未实现 hot_patch_generator 0.8.1 没有 Stream / StreamController / StreamSubscription，也没有 sync* / async* / yield / await for 的翻译分支（构建期告警跳过）。下面整节是设计建议，不是当前实现；落地前需要新增运行时能力模块（capabilities/stream/）。

Dart 的 Stream 是推送模型：有数据就推给订阅者。JS 的 AsyncIterable 是拉取模型：消费者主动取。只把 async* 生成裸 async function*，只能覆盖“有人 await for”这一种用法；源码一旦出现 listen、StreamController、pause 或广播，就不成立。

做法：内部推送给 listen 的订阅者，同时实现 [Symbol.asyncIterator]，把推送事件放进队列供 for await 消费。两种用法共用同一个对象。

// flutter.js 运行时：最小 Stream 实现
class Stream {
  constructor({ broadcast = false } = {}) {
    this._broadcast = broadcast;
    this._listeners = new Set();
    this._pullQueue = [];          // await for 尚未消费的事件
    this._pullWaiters = [];
    this._done = false;
    this._gen = null;              // async* 的生成器
    this._started = false;
    this._asyncIterated = false;   // await for 也占用唯一的订阅位
  }

  listen(onData, { onError, onDone, cancelOnError = false } = {}) {
    if (!this._broadcast && (this._listeners.size > 0 || this._asyncIterated)) {
      throw new StateError('Stream has already been listened to');
    }
    const sub = new StreamSubscription(this, onData, onError, onDone, cancelOnError);
    this._listeners.add(sub);
    this._start();                 // 惰性：首次订阅才拉取生成器
    return sub;
  }

  _emit(type, value) {
    for (const sub of [...this._listeners]) sub._deliver(type, value);
    if (type === 'done') this._done = true;
    const ev = { type, value };
    if (this._pullWaiters.length) this._pullWaiters.shift()(ev);
    else this._pullQueue.push(ev);
  }

  [Symbol.asyncIterator]() {
    if (!this._broadcast && (this._listeners.size > 0 || this._asyncIterated)) {
      throw new StateError('Stream has already been listened to');
    }
    this._asyncIterated = true;
    this._start();
    return {
      next: async () => {
        if (this._pullQueue.length) return this._settle(this._pullQueue.shift());
        if (this._done) return { done: true, value: undefined };
        return this._settle(await new Promise(res => this._pullWaiters.push(res)));
      },
    };
  }

  _settle(ev) {
    if (ev.type === 'error') throw ev.value;          // await for 遇错即中断
    if (ev.type === 'done') return { done: true, value: undefined };
    return { done: false, value: ev.value };
  }

  _start() {
    if (this._started || !this._gen) return;
    this._started = true;
    (async () => {
      try {
        for await (const v of this._gen) this._emit('data', v);
        this._emit('done');
      } catch (e) {
        this._emit('error', e);
        this._emit('done');
      }
    })();
  }

  static fromAsyncGenerator(gen) {
    const s = new Stream();
    s._gen = gen;
    return s;                        // 不解包、不启动，保持 Dart 惰性
  }
}

class StreamSubscription {
  constructor(stream, onData, onError, onDone, cancelOnError) {
    Object.assign(this, { _stream: stream, _onData: onData, _onError: onError,
      _onDone: onDone, _cancelOnError: cancelOnError, _paused: false, _buffer: [] });
  }
  pause() { this._paused = true; }
  resume() {
    this._paused = false;
    while (!this._paused && this._buffer.length) this._deliver('data', this._buffer.shift());
  }
  cancel() {
    this._stream._listeners.delete(this);
    return Promise.resolve();
  }
  _deliver(type, value) {
    if (type === 'data') {
      if (this._paused) { this._buffer.push(value); return; }
      this._onData?.(value);
    } else if (type === 'error') {
      if (this._onError) this._onError(value);
      else if (this._cancelOnError) this.cancel();
    } else if (type === 'done') {
      this._onDone?.();
    }
  }
}

  • Completer、Stream、生成器（sync* / async* / yield）未实现。
为什么补齐放运行时 生成器不带类型解析，只看得到方法名；同名成员按接收者类型分发（挂 Array.prototype 只影响数组，不会误伤同名的控制器方法）。补齐项必须不可枚举、带存在性守卫，禁止挂 Object.prototype。
