00实现总则

这七条是后面所有规则的依据，每条都是硬约束（违反即视为未完成）。实现时先落地这七条，再逐章补特判。

  1. 类型注解全部擦除，但泛型实参必须随尾参下发int、String?、List<T> 等标注不进入产物；但构造与方法的尾参对象必须携带 typeArguments（__ta，已有具名参数时复用 __o），运行时靠它完成 T == X、as T 与 provider 键控。擦注解不等于擦类型身份。
  2. 空安全没有运行时表示，但有运行时可观察行为! / ?. / ?[] / ?? 的语义必须靠改写保住三件事：接收者只求值一次、null 时短路、表达式返回值正确。
  3. 成员翻译只有三种合法写法① 同名直译；② JS 已有同名但语义不同 → _ 前缀 + 构建期映射表（主键 = 接收者内建类型 + Dart 成员名，如 (List, sort) → _sort、(Map, keys) → _keys）；③ JS 缺同名 → 运行时在具体内建原型上用 __defineProtoMember / __defineProtoGetter 补同名。映射只在接收者静态类型可判定为该内建类型时生效；自定义类 / 控制器等其它接收者一律原样，绝不按方法名全局替换；新增映射必须同时改表与手册。禁止为单个成员另写 helper、禁止覆盖原生同名方法（手册明确登记的除外，如 forEach 只在调用点交换参数）、禁止挂 Object.prototype；运行时补齐统一用 Object.defineProperty、enumerable:false + 存在性守卫。
  4. Dart 只有 null，JS 有 null 与 undefined翻译器采用“宽空模型”：凡可能产出 undefined 的位置（Map 未命中、数组越界、可选链短路、缺省实参），判空与取用前先用 __nn 归一（undefined → null，其他值原样返回，不抛错），再用 == null（同时命中两者，禁止 === null），合并统一用 ??。只对可能为空的操作数包：非空类型 / 字面量 / 构造不包，String? / dynamic / 类型不可判定才包。
  5. 编译期概念靠展开，不靠 JS 运行时特性mixin、extension、运算符重载、枚举都是编译期展开；判据只来自源码事实（类表、extends / with 链、import 归属、显式类型注解与项目类构造推断），不做运行时名字猜测，也不维护类型白名单（AGENTS §1 / §5）。
  6. 产物形态与命名必须手册登记产物里出现的每一个非 Dart 名字（包装函数、类名、成员名、前缀、临时对象形态）都必须是本手册表格里登记过的；手册没写的一律不许实现，确需新增时先补手册 + 让开发确认再改代码。典型反例：__map(...) 包装字面量、__Map 类、{__proto__: Map.prototype, …}、__mapLength/__mapKeys。字面量的目标形态（List → []、Map → new Map([[k, v]])）不得擅自更改；改成包装函数 / 额外类 / 原型注入属于改协议，必须先确认，并在同一次变更中更新手册与架构文档。索引改写只允许手册登记的表项：仅 List / 项目类 / 类型不可判定保持原生 a[i]，只有 Map 类型才按手册改写，禁止把辅助函数扩大到 List / 未知类型。新增内部辅助名必须语义完整（如 __makeEnumValue），禁止新增 __mk / __v 这类纯缩写；已发布协议名（__t / __o / __ta 等）保持不动。
  7. 产物必须可验证，且手册先行每条改写规则都要能构造“null 分支 / 非 null 分支 / 求值次数”三个断言，任一不成立即视为实现错误。动手前先定位本手册对应章节（含「翻译原则 / 现状 / 是否通过」）；改完必须在同一次变更中更新对应行、CHANGELOG 与（涉及行为时）示例。手册未更新视为未完成；代码与手册不一致时以手册为准并立即收敛。禁止“先实现再解释”：无法在手册中找到依据的实现，一律停下先确认，不得用“内部原语 / 临时包装 / 为了兼容”绕过约束；新增 __ 前缀原语同属产物形态，必须登记。

01翻译流水

顺序不能乱：名字解析必须早于代码生成，空安全改写必须晚于类型提升分析。

流水线阶段

  • 解析：Dart AST，保留源位置，供报错与生成映射。
  • 类型与流分析（项目现状：不做）：项目用 parseString，没有 analyzer resolution / 流分析 / 类型提升；静态类型只来自显式注解与项目类构造推断，未知即不参与改写（不猜测）。
  • 名字解析（项目现状：类表 + 静态类型）：无符号解析；实例字段 / 方法按类表（含 extends 链）判定，extension 按源码归属改写，不做 import 顺序 / show-hide 冲突解析（冲突项构建期告警）。
  • 节点改写：空安全赋值、?? 括号、mixin 展开、extension 调用重写、枚举/record 结构替换。
  • 代码生成：ES2020 输出，括号按目标语言优先级重建。
  • 自检：求值次数、短路、返回值三类断言。
依赖以 JS 产物为准 Dart 的 import / 类型引用只是候选依赖；只有该引用真的进入产物（目标类、顶层常量或顶层函数被发射，且调用点被翻译）才形成依赖。JS 侧依赖链断开时（类没有产出、语句被丢弃、成员未翻译），不得为了 Dart 依赖强行发射目标文件。典型：应用壳 main.dart / app_log_console.dart 只被宿主入口引用，不进入补丁；它们的顶层常量 / 函数不因文件可达而产出。
引擎能力边界（硬约束） 产物实际运行在 Android QuickJS 2021-03-27（flutter_js 0.8.7 内置）与 iOS 15+ 的 JavaScriptCore 上，语法基线是 ES2020 + 部分 ES2021（??= / ||= / &&=、Promise.any、AggregateError、String.replaceAll）。禁止在产物或运行时使用两端引擎未实现的 API：Object.hasOwn、Array/String.prototype.at、findLast / findLastIndex、class static block（static {}）、top-level await、structuredClone、WeakRef / FinalizationRegistry（后两项属 ES2021，但 QuickJS 2021-03-27 也未实现）。需要同等能力时在运行时补同名实现或改用 ES2020 写法。
为什么先做名字解析再做代码生成 extension 调用、mixin 成员复制、运算符重载都依赖“这个标识符到底指向谁”。先把符号绑定定下来，代码生成阶段才能只做局部改写，不用回头重扫全树。

DART → JS · 深度冻结

// const 集合：递归冻结，Map/Set 需要单独包一层
function deepFreeze(v) {
  if (v instanceof Map) {
    for (const [k, x] of v) deepFreeze(x);
    Object.freeze(v);           // 仍可 set，语义上需要冻结代理
    return v;
  }
  if (v instanceof Set) {
    for (const x of v) deepFreeze(x);
    Object.freeze(v);
    return v;
  }
  if (v && typeof v === 'object') {
    for (const k of Object.keys(v)) deepFreeze(v[k]);
    Object.freeze(v);
  }
  return v;
}
Map 的冻结陷阱 Map 字面量现在是原生 new Map([[k, v], …])；Object.freeze(new Map()) 并不能阻止 set，因为数据存在内部槽而非属性上。项目不伪造 const 的不可变语义（与 List 一致，Dart 的 const 是编译期保证），因此不冻结、不做只读代理；把这条记为「不适用 / 不实现」，不要为了“冻结”再造包装形态。

逻辑运算符的返回值类型不同

Dart 的 && / || 结果类型是 bool；JS 返回操作数本身。语句位置（if）无差异，作为值存储或跨语言传递时必须归一。

// Dart
bool ok = a || b;        // ok 一定是 true / false

// JS 直译：ok 可能是 a 本身（对象、字符串…）
const ok = a || b;

// ✅ 作为值使用时归一

惰性 vs 立即求值

Dart 的 map / where / expand / take / skip 返回惰性、可重复迭代的 Iterable；JS 数组方法立即求值并返回新数组。项目保持调用点同名：where / expand / take / skip 在 Array / Set / 生成器原型上的同名实现直接返回 LazyIterable（保存迭代器工厂，每次迭代重新执行回调）；map 因为不能覆盖原生 Array.prototype.map，由生成器按映射表改名为 _map（与 sort → _sort / join → _join 同一规则，只对可判定为 List / Iterable 的接收者生效）。__iter* 是这些原型实现共用的内部原语，不直接出现在产物里。

// 产物形态（调用点保持 Dart 写法）

const again = b.toList();                  // 再执行一遍（可重复迭代）

extension 扩展成员

当前方案（本项目）

选择原型注册而不是编译期静态分派，原因是本项目只有源码级静态判定、没有完整类型推断：表达式的接收者类型经常不可判定，照搬静态分派会让大量调用退化成“无法改写”。原型注册让调用点保持 Dart 原样（x.m() 仍是 x.m()），且 registerExtension 的稳定 id 支持热更时先卸载再重注册。显式 E(x).m() 是唯一的身份分派形态（必须按扩展名绑定）。作为参照，dart2js 的做法是把扩展成员编译成模块内顶层函数、在调用点静态改写成函数调用（不碰原型），本项目未采用该形态。

  1. 成员（方法 / getter / setter / 运算符）编译成目标类型原型上的同名成员；声明所在的产物求值时执行一次 registerExtension(Target, { members }, { id })。
  2. 函数成员由严格模式函数承载，this 就是接收者（避免原始值装箱），与 Dart 的 this 语义一致。
  3. 调用点保持 Dart 原样：x.m() / x.m 直接落到 JS 成员读取；实例成员优先由原型的同名成员承接。运算符无 JS 语法，声明侧改名 __op$add / __op$neg …，调用点按接收者静态类型改写成 receiver.__op$xxx(args)。
  4. 静态成员放在 extension 命名空间对象上（E.foo 原样访问）。
  5. 目标类型必须在 JS 侧有可挂载的原型（核心类型 / 运行时注入类 / 项目类）；Map / Object / dynamic / 宿主 widget 等没有单一实体原型的注册在构建期拒绝。

顺序与覆盖 with M1, M2 中 M2 优先级最高：application 链按书写顺序生成，M2 在更派生的一层；__mixinHard 只填充目标尚无自有同名成员的位置，因此 M2 覆盖 M1。类自身声明写在最终 C 上，优先级最高。
调用时机：__mixinHard 一律放在本模块全部类声明之后——mixin 类可能声明得比 application 类晚，类声明之间调用会触发 TDZ（Cannot access 'M' before initialization）。

红线

  • 不要把 mixin 成员内联进最终类（C 里不应出现 A.log）；成员只在 mixin 产物 / application 层。
  • 不要用 Object.assign(C.prototype, M.prototype)：原生 class 方法不可枚举，且会绕过「目标已有同名自有成员不覆盖」的优先级规则；用 __mixinHard 的自有属性描述符复制。
  • 不要跳过 mixin 的原文件产物直接在本文件合并——消费者必须 import 该 mixin 类。
  • mixin 字段不要在最终类构造里重复初始化；由 application 类构造按 with 顺序负责。
  • 字段初始化顺序：superclass 构造 → 各 mixin 按 with 顺序初始化 → 子类构造体。

② 背压：单订阅有订阅者暂停时停止拉取上游（async* 停在 yield）；广播不传播暂停。
③ 取消：最后一个订阅者 / 拉取者离开时取消上游并 await 清理（iterator.return()）——break、take(1)、循环体抛错、cancel() 已走同一路径；await for 遇到 stream error 退出时不取消（不通过，见下表）。
④ 错误：交付 onError 后 cancelOnError 独立生效（与是否提供 onError 无关）。
⑤ close：Future 在订阅者处理完 done 后完成（暂停订阅者等到 resume）；无订阅者同 tick、取消后再 add 两种场景与 Dart 不一致（不通过，见下表）。
⑥ 转换：map / where / expand / take / skip / distinct / asyncMap 一律「订阅上游 + 转发事件」（不是 for await 循环）：一次 error 不会终止下游流，也不遗留上游订阅。

Dart 的 Stream 是推送模型：有数据就推给订阅者。JS 的 AsyncIterable 是拉取模型：消费者主动取。只把 async* 生成裸 async function*，只能覆盖“有人 await for”这一种用法；源码一旦出现 listen、StreamController、pause 或广播，就不成立。

// flutter.js 运行时（stream_js.dart 结构摘要）：显式事件 + 订阅状态机
class Stream {
  constructor({ broadcast = false, source = null, onListen = null } = {}) {
    this._broadcast = broadcast;
    this._source = source;           // async* 产物：() => AsyncIterator
    this._onListen = onListen;
    this._subs = new Set();          // listen 订阅者
    this._pullers = new Set();       // await for 拉取方
    this._pending = [];              // 单订阅：首个订阅者出现前的事件
    this._readyWaiters = [];         // 背压：等待需求唤醒
    this._iterator = null;           // 当前 async* 迭代器
    this._asyncIterated = false;     // await for 也占用唯一的订阅位
    this._done = false;
    this._started = false;
    this._stopped = false;
  }

  listen(onData, { onError, onDone, cancelOnError = false } = {}) {
    if (!this._broadcast && (this._subs.size > 0 || this._asyncIterated)) {
      throw new StateError('Stream has already been listened to');
    }
    const sub = new StreamSubscription(this, onData, onError, onDone, cancelOnError);
    this._subs.add(sub);
    for (const ev of this._pending.splice(0)) sub._enqueue(ev.type, ev.value);
    this._start();                 // 惰性：首次订阅才拉取生成器
    return sub;
  }

  _emit(type, value) {             // 事件异步投递：add() 调用栈内不触发回调
    return Promise.resolve().then(() => this._deliverEvent(type, value));
  }

  _deliverEvent(type, value) {     // 唯一分发出口：单订阅 / 广播 / 拉取方
    if (this._subs.size === 0 && this._pullers.size === 0) {
      if (!this._broadcast) this._pending.push({ type, value });  // 广播：丢弃 data / error
      return;
    }
    for (const sub of [...this._subs]) sub._enqueue(type, value);
    // 拉取方：有等待中的 next 直接交付，否则进队列
  }

  async _pump() {                 // async* 源：先等需求（背压）再 next
    while (!this._stopped) {
      await this._waitDemand();
      const r = await this._iterator.next();
      if (r.done) { await this._emit('done'); return; }
      await this._emit('data', r.value);   // 等这一项被消费，避免多生产
    }
  }

  static fromAsyncGenerator(gen) {
    return new Stream({ source: () => gen });   // 不解包、不启动，保持 Dart 惰性
  }
}

class StreamSubscription {
  constructor(stream, onData, onError, onDone, cancelOnError) {
    Object.assign(this, { _stream: stream, _onData: onData, _onError: onError,
      _onDone: onDone, _cancelOnError: cancelOnError, _paused: false, _queue: [] });
  }
  pause() { this._paused = true; }
  resume() {
    this._paused = false;
    this._drain();
    this._stream._wake();          // 恢复接收 → 允许上游继续拉取（背压）
  }
  cancel() {                       // 传播取消并 await 上游 iterator.return()
    this._stream._subs.delete(this);
    return this._stream._cleanupIfIdle();
  }
  _enqueue(type, value) { this._queue.push({ type, value }); this._drain(); }
  _drain() {                       // 暂停期间 data / error / done 全部缓冲
    while (!this._paused && this._queue.length) {
      const ev = this._queue.shift();
      this._deliver(ev.type, ev.value);
    }
  }
}

七个必须建模的语义 ① 惰性：async* 在首次订阅前不能执行函数体；包装时立刻 for await 会让 initState 里创建的流提前开跑。
② 单订阅与广播：单订阅流第二次 listen 抛 StateError；广播流每个订阅者独立，无订阅者时 data / error 直接丢弃（done 粘滞给后续订阅者），pause 期间与单订阅一样按订阅者缓冲（与 Dart 实测一致）。
③ 错误不终止流：listen 的 onError 处理完流继续，只有 cancelOnError 才取消订阅；await for 遇错则中断，所以 asyncIterator 必须 throw。未对齐：Dart 在 await for 因错误退出时会取消订阅，当前只中断、不取消（不通过）。
④ 背压：单订阅流 pause 后缓冲事件并停止拉取上游（async* 停在 yield），resume 按序补发后继续拉取；广播不向源传播暂停（事件进各订阅者队列）。
⑤ StreamController 的 onListen 惰性：第一次 listen 才触发 onListen，close 之后不能再 add。
⑥ 单订阅一生一次 / 错误不静默：取消后再次 listen 或 await for 抛 StateError；无 onError 的错误经 __error 上报；onError 第二参为栈字符串（addError 未给栈时为空串，对应 Dart StackTrace.empty；生成器 throw 取 Error.stack）。
⑦ close / done / onCancel 生命周期：Dart 的单订阅流在 cancel() 后不再缓冲（add 丢弃、close() 立即完成），done 交付后订阅自动取消（hasListener=false），广播的 onListen / onCancel 按订阅周期成对触发。当前四项均未对齐：取消后 _pending 仍累积导致 close() 挂起、无订阅者同 tick close() 提前完成、done 后订阅留在 _subs、广播 onCancel 只触发一次（见上表不通过行）。
