从零接入，并完成本地联调

组件本体不做任何改造：构建期由生成器把它静态翻译成同名 JS 模块；线上出问题时，运行时把该组件切换到 JS 版本加载，逻辑跑在 JS 侧、渲染仍在原生 Flutter 侧。

整体模型

三个包各司其职，业务代码只依赖注解与运行时：

包阶段职责
dynamic_flutter_annotations编译期声明式注解：@PatchEntry / @PatchIgnore / @HostInjected
dynamic_flutter_generator编译期按语法规则把 Dart 源码翻译成等价 JS 产物，并组装补丁包
dynamic_flutter运行期JS 运行时 + 宿主渲染 + 能力桥；JsUiWidget 是唯一页面入口
i

组件在未被热更引用时就是普通 Flutter widget，照常原生渲染；只有被 JsUiWidget 加载的补丁才会走 JS 版本。接入是渐进式的，可以只对少数高风险页面生效。

接入四步

1

加依赖

业务 App 的 pubspec.yaml：

dependencies:
  dynamic_flutter_annotations: ^0.1.5   # 注解
  dynamic_flutter: ^0.4.2               # 运行时

dev_dependencies:
  dynamic_flutter_generator: ^0.13.0    # 构建期翻译（dev 依赖，不进包体）
  build_runner: ^2.4.13
flutter pub get
i

生成器的 builder 只对声明了该 dev 依赖的包生效。子包没加依赖，就不会产出对应的 patch/<package>.js。

2

给组件打注解

import 'package:flutter/material.dart';
import 'package:dynamic_flutter_annotations/dynamic_flutter_annotations.dart';

@PatchEntry('Counter')            // name 可省略，缺省取类名
class Counter extends StatefulWidget {
  const Counter({super.key});

  @override
  State<Counter> createState() => _CounterState();
}

class _CounterState extends State<Counter> {
  int _count = 0;                                  // 非 static 字段 → JS 状态
  void _inc() => setState(() => _count++);          // 方法 → JS 方法

  @override
  Widget build(BuildContext context) => Column(
        children: [
          Text('count = $_count'),
          ElevatedButton(onPressed: _inc, child: const Text('+1')),
        ],
      );
}

收集口径是整个 widget，不做字段 / 方法级标注：非 static 字段成为 JS 状态，普通方法成为 JS 事件方法，build() 是 JS 渲染入口，SnackBar 形式的方法自动识别为原生通道。

3

生成产物

dart run build_runner build --delete-conflicting-outputs

产物落在 patch/，与 lib/ 源码路径一一对应。patch/ 下所有 JS 都是生成物，不要手改：修 bug 改 Dart 单源或生成器，然后重跑构建。

4

声明资源并加载

线上一般把 patch.zip 放到 CDN / 静态服务，让 jsAsset 直接指向 zip；运行时下载解压后，按与本地 asset 相同的规则加载入口模块。

JsUiWidget(
  jsAsset:
      'https://cdn.example.com/dynamic_flutter/patch.zip'
      '?component=Counter'                // 必填：入口模块里注册的组件类名
      '&entry=components/counter.js'     // 可选：zip 内入口 JS 的相对路径
      '&lang=zh_CN',                     // 运营配置：进入业务 props
  params: const {'theme': 'dark'},        // 开发固定参数
)
  • component 必填；entry 不传时按组件名反查入口模块。
  • 除 component / entry 外的 query 都会合并进 props；同一 key 以 URL 为准，URL 值按字符串处理。
  • zip 根目录保持产物布局：manifest.json、runtime.js、flutter.js、components/…、packages/…。
  • 补丁更新只需替换服务端 zip，App 无需发版；运行时按 manifest.json 的身份版本判断是否需要切换。
i

本地联调同样走 HTTP：http://127.0.0.1:8765/patch/patch.zip?component=Counter&entry=components/counter.js，产物不必打进 App。

!

只有必须随包内置时才用本地 asset：Flutter 的目录 asset 声明不递归，需在 pubspec.yaml 的 assets: 里逐目录 / 逐文件列出，然后写 jsAsset: 'assets/patch/components/counter.js?component=Counter'。目录漏声明是最常见的「加载不到产物」原因。

产物布局

源码 / 输入产物说明
lib/components/counter.dartpatch/components/counter.js含 @PatchEntry 的组件
lib/model/user.dartpatch/model/user.js被可达组件引用到的普通类 / 静态单例
宿主 js/<package>.jspatch/packages/<package>.js三方库 / 业务自定义组件的 JS，原样拷贝（见 接入三方库）
包根伪资产 $package$patch/flutter.jsFlutter SDK 的 JS 面：宿主组件包装类、值类、JS 逻辑组件
包根伪资产 $package$patch/runtime.js整个 JS 运行时；随补丁发布，改运行时无需发版 App
包根伪资产 $package$patch/manifest.json协议版本、打包时间、各资源内容 hash
上述全部patch.zip由 ui_patch_archive 归档，供远程下发

分流按文件内容 + 引用可达性判断，与目录结构无关：含 @PatchEntry 的文件是根文件；否则只有真的被可达类引用到的类才产出。既不可达也未被引用的文件不产出。

运行时接入

JsUiWidget 参数

参数说明
jsAsset补丁入口 JS（asset 路径或 http(s)://...zip），必填
params传给组件构造的业务参数；与 jsAsset query 合并，同 key 以 URL 为准
showBuildTime调试开关：右上角显示补丁打包时间（取自 manifest.json），不参与命中测试

三种补丁源

  • http(s)://host/xxx.zip?component=Name&entry=path/to.js：网络补丁包（生产默认），下载解压后与 asset 走同一加载逻辑；component 必填，entry 可选（zip 内入口 JS 相对路径）；
  • assets/patch/...js：随包资源（仅本地 / 离线场景）；
  • 同一 JS 运行时里其它已加载模块。
!

运行时是全局唯一实例（JsRuntimeManager.instance），不支持创建第二个实例或做分组隔离。同一进程内所有 JsUiWidget 必须指向同一补丁包身份（同一 zip / 同一批次）；身份版本变化会清空已加载模块并重载所有挂载页面。

宿主方法通道

JS 侧唯一出口是 _app_host_.invoke(channel, args)，宿主侧唯一入口是 JsRuntimeManager.registerHostMethod。业务只需声明 @HostInjected，生成器会产出注册清单：

class HostGreeter {
  @HostInjected()
  static String greet(String name) => 'Hi, $name';
}

void main() {
  registerHostMethods();   // 生成于 lib/generated/host_methods.dart
  runApp(const MyApp());
}

JsRuntimeManager.navigatorKey 需传给 MaterialApp.navigatorKey：热更包里的 toast / 路由推页靠它定位 Navigator 与 ScaffoldMessenger。

日志与上报

包内日志与报错统一从 JsLog 流出；本地打印与上报彼此独立，注册一个 sink 即可接到自己的日志平台：

JsLog.sink = (r) => MyLogPlatform.upload(
      level: r.level.name,          // debug / info / warn / error
      message: r.message,
      error: r.error,
      stack: r.stackTrace,
      time: r.time,
    );
JsLog.minSinkLevel = JsLogLevel.info;   // 默认 warn
JsLog.enabled = false;                     // 只关本地打印

本地联调

示例 App 在 example/，业务 Dart 单源在 example/lib/，产物在 example/patch/。

# 仓库根：build_runner 生成产物（含 patch.zip）→ 重启本地服务
bash start_patch_server.sh

# 运行示例 App（补丁由上面的服务提供）
cd example && flutter run

服务地址 http://127.0.0.1:8765/，两类路由：

  • GET /patch/<相对路径> 返回 example/patch/ 下对应文件，GET / 列目录；
  • 其余路径是 mock 接口：按 URL 路径读取 tool/mock/<路径>.json 原文返回，新增接口只需放一个同路径 json。

服务日志在 /tmp/patch_server.log。示例补丁 URL 形如：

http://127.0.0.1:8765/patch/patch.zip?component=HelloCard&entry=components/hello_component.js
i

验证闭环：只改 Dart 业务源码 → 重跑 bash start_patch_server.sh → 在 App 里重进该页面即可看到新产物。改运行时 JS 源后重跑 build_runner 并重进 / 重载页面生效，不需要重装 App。

常见问题

现象原因 / 处理
patch/<package>.js 没产出该包没把 dynamic_flutter_generator 加进 dev_dependencies；确认依赖后重跑构建
运行时加载不到产物目录 asset 声明不递归，需逐目录 / 逐文件在 assets: 中列出
组件结点渲染成红底占位该组件被 @PatchIgnore 或跨库不可见，运行时未注册宿主实现；在 main() 用 jsWidgetRegistry.register 注册，见 自定义组件
debug 下出现 <ui fallback: …>渲染兜底统一出口；按括号里的原因定位（结点丢失、子元素解析失败、builder 下标越界等）
改了 Dart 但页面没变patch 服务没重跑，或 App 未重进页面
某个 Dart 写法热更后行为不对先查组件支持文档「已知限制」，再确认产物不是被手改过
