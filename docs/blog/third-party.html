Guide · 接入三方库

三方库的 JS，由业务在自己的工程里维护

生成器不内置任何三方库的 JS。你在工程根建一个 js/ 目录，文件名即 Dart 包名；构建时原样拷贝进补丁包，业务产物按相对路径 import。需要宿主真值时，再按能力扩展点注册桥接。

机制：谁来维护三方 JS

三方库的 JS 形态取决于具体库、具体版本，也无法由语法规则自动推导。因此框架把它划给业务方维护：

  • 三方可翻译的部分：业务写在工程根 js/<package>.js，构建期原样拷贝，不改一行；
  • 三方库自己的运行期登记（继承结点、原型补丁、枚举常量）也写在同一个模块里；
  • 三方库需要的宿主能力（真实 widget、Controller、平台通道）经 JsUiLibrary 注册，dynamic_flutter 核心零改动。
i

这与「新增一个 Flutter 内建组件」是同一条扩展路径：编译期统一翻译，运行期按 type 查注册表。三方库只是把 JS 类的归属从框架产物换成了业务模块。

目录与产物

工程内补丁包内说明
js/provider.jspatch/packages/provider.js文件名即 Dart 包名（package:provider）
js/easy_refresh.jspatch/packages/easy_refresh.js原样拷贝，构建期不做改写
js/ 为空无三方产物零产物，构建正常

产物通过相对路径消费：

// patch/components/order_page.js 里由生成器产出
import { ChangeNotifierProvider, Consumer } from '../packages/provider.js';
i

不需要改 build.yaml 的 sources：ui_third_party_js 按文件系统扫描 js/，放文件即生效。三方库 JS 不会进 patch/flutter.js——框架产物只承载内建宿主组件。

三类三方库

类型例子JS 模块要做什么宿主侧
纯值类 / 工具类 uuid、path_provider、dio 写同名类 / 方法；构造实参由生成器映射成对象 无
状态管理 / 无宿主结点 provider、get 把状态与订阅闭环在 JS；需要时登记继承结点 / 全局实例表 无
视觉组件 / 平台能力 visibility_detector、easy_refresh 写宿主元素包装类；函数形参列进 __fnProps 需要 JsUiLibrary 注册桥接

分步接入

1

写 js/<package>.js

纯值类：构造实参由生成器按 Dart 构造签名映射成对象，方法同名实现即可。

// js/uuid.js
export class Uuid {
  constructor(args) {
    var a = args || {};
    this.options = a.options || null;
  }

  v4() {
    // … 返回 UUID 字符串
  }
}

视觉组件：继承 Component，构造即宿主结点；type 名取类名。

// js/visibility_detector.js
import { Component } from '../flutter.js';

export class VisibilityDetector extends Component {
  // 只有需要跨桥换成句柄的函数形参才列在这里
  static __fnProps = ["onVisibilityChanged"];
}

三方枚举：SDK 枚举由 flutter.js 自动生成，三方包的枚举必须由你自己的模块补齐，跨桥时 toJSON() 发成员名。

export class IndicatorMode {
  constructor(name, index) {
    this.name = name;
    this.index = index;
  }
  toJSON() { return this.name; }
  valueOf() { return this.name; }
  static inactive = new IndicatorMode('inactive', 0);
  static drag = new IndicatorMode('drag', 1);
  // …
}
2

Dart 业务照常写

业务代码仍然 import 真实的三方包、按 Dart 语法使用。生成器按「类声明所在包 + 该包是否有 js/<package>.js」自动决定产物里的 import 归属：

import 'package:provider/provider.dart';
import 'package:visibility_detector/visibility_detector.dart';
!

源码用到了某三方包的类型，但 js/<package>.js 缺失 → 构建期直接报错，构建失败。不会等到运行期才暴露，产物里也不会留下指向缺失模块的 import。

3

需要宿主真值时，注册 JsUiLibrary

只有在 JS 无法自己给出结果时才注册宿主桥接（例如可见比例、原生手势、真实 Controller）：

class CustomEasyRefreshLibrary extends JsUiLibrary {
  const CustomEasyRefreshLibrary();

  @override
  String get id => 'easy_refresh';

  @override
  void ensureChannels() => ensureEasyRefreshChannels();

  @override
  void registerWidgets(JsWidgetRegistry r) => registerEasyRefreshWidgets(r);
}

两个钩子各管一段：

钩子用途
ensureChannels()幂等登记跨语言句柄 kind（如 Controller）
registerWidgets(r)登记 type → 真实 Flutter widget
4

注册与验证

void main() {
  WidgetsFlutterBinding.ensureInitialized();
  registerJsUiLibrary(const CustomEasyRefreshLibrary());   // runApp 之前
  runApp(const MyApp());
}
dart run build_runner build --delete-conflicting-outputs

确认 patch/packages/<package>.js 已产出、产物里的 import 路径正确，再重进页面观察行为。

归属与报错

  • 归属判据：类声明所在包 + 该包是否存在宿主 JS 模块。没有库 / 类型白名单，也不按类名猜测。
  • 自动 import：业务产物按相对路径 import 对应模块；枚举声明同样按包归属补 import。
  • 缺失即失败：有 pub 依赖类型但缺 js/<package>.js，构建期报错，禁止静默降级。
  • 不手改产物：patch/ 下所有 JS 都是生成物；改 JS 类请改 js/<package>.js，再重跑构建。
  • 引擎基线：模块与产物共用 ES2018 / ES2020 基线（iOS 15+ JavaScriptCore、Android QuickJS），不要使用 Object.hasOwn、Array.prototype.at、class static block、top-level await 等未实现能力。

控制器 / 异步 / 懒容器

Controller 句柄

三方库的 Controller 与 ScrollController 共用同一套通用句柄层（JsControllerBridge）：JS 侧 new XxxController({...}) 同步到宿主创建真实实例，控制方法走通用 op，释放走通用 release。业务 JS 模块无需自己实现通道。

final JsControllerBridge<EasyRefreshController> _bridge =
    JsControllerBridge<EasyRefreshController>(
  kind: 'ctrl/EasyRefresh',
  create: (_, meta) {
    final m = meta is Map ? meta : const <Object?, Object?>{};
    return EasyRefreshController(
      controlFinishRefresh: m['controlFinishRefresh'] == true,
    );
  },
  onOp: (c, op, payload) { /* 按方法名分发 */ },
  onRelease: (c) => c.dispose(),
);

返回 Future 的事件

宿主发起、需要等 JS 完成任务的事件（如 EasyRefresh 的 onRefresh）走通用 JsRuntimeManager.invokeAwait(handler)；JS 侧 await 完成后经 jsuiEventResult 回传 token 与结果。这是通用机制，不是某个库专属。

三方容器与懒加载

三方组件的 JS 类由你在 js/<package>.js 里维护，懒加载也直接在类上声明，不需要改生成器或 dynamic_flutter：

import { Component } from '../flutter.js';

export class MyCarousel extends Component {
  // __lazy 是「懒规则」，类型为 boolean | string[]：
  static __lazy = true;              // true = 无条件懒
  // static __lazy = ['autoPlay'];  // 数组 = 仅当这些 props 任一存在时才懒
}
  • __lazy 的取值：true 无条件懒；string[] 条件懒（如自定义轮播组件只在带 autoPlay 时懒）；不写或 false 表示不懒。
  • 声明必须落在宿主元素类上：继承 Component 且不重写 build，由基类在构造期读取并标记 lazyChildren。
  • 如果类重写了 build（逻辑组件），自身不产生宿主元素；应在它创建宿主结点的位置（Component.host(type, props, lazy)）传入 lazy 规则。
  • lazyChildHostTypes / builderFormTypes 只作用于生成器产出的包装类（内建 SDK 组件、@PatchIgnore(isComponent: true) 的包装类），对 js/<package>.js 里手写的类不生效，也无需登记。

自定义列表容器：宿主按槽位拉取

export class MyHorizontalList extends Component {
  build(context) {
    const p = this.props;
    // 与懒槽位同一套协议：内部标记 + 统一 __builder
    // 组件差异在这里折叠：数量字段叫什么、回调签名怎样，都由本类决定
    return Component.host('MyHorizontalList', {
      ...p,
      __pullItems: true,
      __builder: {
        item: (ctx, slot) => p.itemBuilder(ctx, slot),
        slots: p.itemCount ?? 0,
        ctx: context,
      },
    }, false);
  }
}
  • runtime 只认 __builder = {item(slotIndex), slots} 与 __pullItems 标记，不认识类型名、数量字段名；宿主要为该类型注册 renderer，并在 itemBuilder 里用 c.lazySlot(i) 取子项。
  • 这个类如果是「只继承 Component 空 build 的宿主元素类」，也可以在类上写 static __lazy 走懒槽位；两种路径按子项是否定高选择。
!

只有「子项尺寸由容器强制」的容器才能用 __lazy 懒槽位（如分页、网格）。按内容量尺寸的容器（Column 类、自定义自适应高度列表）不要设 __lazy：JS 侧用 0×0 占位结点替代真实子项，占位必须布局中性；按内容量尺寸时 0 高占位会让内容总高度塌陷、视口把所有项判为可见，懒加载反而失效。内建 ListView.builder / .separated 走的是另一条路——宿主按槽位拉取（pullChildHostTypes），不需要 itemExtent；业务代码直接照常写 ListView.builder 即可。

常见问题

现象原因 / 处理
构建报错：找不到三方模块源码用了该包的类，但工程根缺少 js/<package>.js；文件名必须与 Dart 包名一致
patch/packages/ 下没有文件js/ 目录为空或文件不在工程根；确认构建执行的是宿主工程
运行时提示组件未注册视觉组件未在 main() 里 registerJsUiLibrary；见 自定义组件
事件回调不触发函数形参未列进 JS 类的 __fnProps，跨桥时没有换成句柄
枚举值跨桥后变成对象三方枚举未实现 toJSON() 返回成员名
改了 js/xxx.js 但行为没变没重跑 build_runner，或 App 未重进页面
