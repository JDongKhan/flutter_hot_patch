# UI Component 组件支持文档

> 本文档列出 `hot_patch_generator`（生成器）当前支持的 Flutter 组件、属性与写法约束。
> 生成器把 `@PatchEntry` 注解类（含 `build()` 树）翻译为 JS 产物；`hot_patch` 运行时把产物还原为真实 Flutter widget（原生 vs JS 热更共用同一套属性协议）。
>
> **对齐口径**：生成器侧只有一条翻译路径 `packages/hot_patch_generator/lib/src/builders/patch_entry/translator/widget_json.dart`（通用参数名）+ `value_forms.dart`（值的形态，含 `style_translators.dart` 的结构化样式）；产物形态登记表在 `lib/src/builders/shared/js_widget_defs.dart`。运行时侧 `packages/hot_patch/lib/src/json/flutter_from_json.dart` + `js_ui/js_widget_registry.dart`（及能力域 `js_ui/capabilities/*`）。两端对称，新增属性必须同时改两侧。
>
> **产物协议**：所有 Dart 实参按原名进 `props`（`child` / `children` / `slivers` / `tabs` 也是普通具名实参）。元素工厂 `__h` 在运行时按**值形态**拆分：值是元素（`element: true`）或元素数组 → 按原名进 `children`，delegate 描述同样进 `children`，其余留在 `props`；**与键名无关**，`content` / `top` / `body` / `actions` 走同一套协议。JS 组件类（type 是函数）保留全部 props 供 `__applyProps`。位置实参按 Flutter 形参名下发（`Text('hi')` → `{data: 'hi'}`），未登记形参名的类型构建期告警并丢弃；命名构造 / 静态工厂名进 `props.factory`（`{factory: 'separated', itemBuilder: …, separatorBuilder: …}`），运行时按 **type + factory** 选原生工厂。builder 形态只认显式协议：命名构造由代理类展开到 `children.__items`，delegate 形态是 `children.delegate = {__delegate: 'builder', builder, childCount}`。枚举引用（`Axis.horizontal` / `BottomNavigationBarType.fixed`）→ **成员名字符串**（JS 侧没有枚举，裸标识符会 ReferenceError）。`on*` 回调按**最终消费方**分流：JS 侧组件（有 JS 产物 / 逻辑组件）下发**可调用闭包**；宿主 widget（含 builder 代理透传给宿主的 props）下发事件句柄 `{__fn:id}`。

## 1. 组件支持矩阵

### 1.1 布局类

| 组件 | 支持属性 | 说明 / 限制 |
|---|---|---|
| **Column** / **Row** | `children`、`mainAxisSize`、`mainAxisAlignment`、`crossAxisAlignment` | 主轴枚举：`MainAxisSize.min/max`；`MainAxisAlignment.start/center/end/spaceBetween/spaceAround/spaceEvenly`；`CrossAxisAlignment.start/center/end/stretch/baseline` |
| **Expanded** / **Flexible** | `flex`、`child` | 仅用于 Row/Column 内；`flex` 需整数字面量 |
| **Spacer** | `flex` | Row/Column 内弹性空隙；`flex` 需整数字面量（默认 1） |
| **Center** | `child` | 单子 |
| **Padding** | `padding`、`child` | `padding` 支持 `EdgeInsets.all/symmetric/only/fromLTRB`，见 §3.1 |
| **Align** | `alignment`、`child` | `alignment` 支持 `Alignment.center/topLeft/topCenter/topRight/centerLeft/centerRight/bottomLeft/bottomCenter/bottomRight` |
| **Stack** | `children`、`alignment`、`fit`、`clipBehavior` | `fit` 支持 `StackFit.loose/expand/passthrough`；`clipBehavior` 见 §3.5 |
| **IndexedStack** | `index`、`children`、`alignment` | 只显示 `index` 指定的单子；`index` 支持状态字段表达式 |
| **Positioned** | `left`、`top`、`right`、`bottom`、`width`、`height`、`child` | 仅用于 Stack 内；数值需字面量；支持 `Positioned.fill(...)`（四边默认全 0 撑满，显式参数可覆盖偏移） |
| **SizedBox** | `width`、`height`、`child` | 可带 child（如 `SizedBox(height:100, child: Stack(...))`） |
| **Wrap** | `children`、`spacing`、`runSpacing`、`direction`、`alignment`、`runAlignment`、`crossAxisAlignment` | `spacing`/`runSpacing` 需数字字面量；`direction` 为 `Axis.*`；`alignment`/`runAlignment` 为 `WrapAlignment.*`；`crossAxisAlignment` 为 `WrapCrossAlignment.*` |
| **SafeArea** | `child`、`left`、`top`、`right`、`bottom` | 四边开关为 bool 字面量（默认 true） |
| **Opacity** | `opacity`、`child` | `opacity` 需数字字面量 |
| **ConstrainedBox** | `constraints`、`child` | `constraints` 见 §3.6 BoxConstraints |
| **AspectRatio** | `aspectRatio`、`child` | `aspectRatio` 需数字字面量 |
| **FractionallySizedBox** | `widthFactor`、`heightFactor`、`alignment`、`child` | 因子需数字字面量 |
| **SingleChildScrollView** | `child`、`scrollDirection`、`padding`、`physics`、`reverse`、`controller` | `scrollDirection` 支持 `Axis.horizontal/vertical`；`physics` 见 §3.7；`controller` 透传 JS ScrollController 句柄 |
| **ListView** | `children`、`scrollDirection`、`padding`、`shrinkWrap`、`physics`、`itemExtent`、`controller` | 列表子项走通用翻译（含 for 循环展开）；`shrinkWrap` 缺省保持 Flutter 默认 `false`；`ListView.builder` / `ListView.separated`（itemBuilder + itemCount）已支持，闭包抽为组件方法由代理类展开、宿主还原原生构造 |
| **GridView** | `children`、`gridDelegate`、`scrollDirection`、`padding`、`shrinkWrap`、`physics`、`controller` | 四种形态：普通构造 / `GridView.builder`（itemBuilder + itemCount，同 ListView.builder 机制）/ `GridView.count(crossAxisCount:)` / `GridView.extent(maxCrossAxisExtent:)`（便捷参数进 props） |
| **ReorderableListView** | `children` 或 `.builder`（`itemBuilder` + `itemCount`）、`scrollController`、`onReorder`、`scrollDirection`、`padding`、`shrinkWrap`、`physics` | 拖拽排序列表；children 需各自带 `ValueKey`；`onReorder` 为 (oldIndex, newIndex) 双值事件；`.builder` 与 ListView.builder 同机制（代理类展开子树、宿主还原原生命名构造）；controller 形参名是 `scrollController`（不是 ListView 的 `controller`），走同一套滚动控制器桥接 |
| **CustomScrollView** | `slivers`、`scrollDirection`、`physics`、`reverse`、`shrinkWrap`、`controller` | sliver 容器；`slivers` 按原名进 `children` 的数组 slot |
| **SliverList** | `delegate` 或 `.builder` / `.separated` | `delegate` 支持 `SliverChildListDelegate([...])`（children 展开）与 `SliverChildBuilderDelegate((c,i) => w, childCount: n)`（闭包抽方法）；`.builder` / `.separated`（itemBuilder + itemCount，+ separatorBuilder）同样闭包抽方法 |
| **SliverGrid** | `delegate`（同 SliverList）、`gridDelegate` | 支持 `.builder` 命名构造；gridDelegate 数值同 GridView |
| **SliverFixedExtentList** | `delegate`（同 SliverList）、`itemExtent`（必填） | 固定行高 sliver 列表 |
| **SliverFillViewport** | `delegate`、`viewportFraction`、`padEnds` | 按视口分数分页的 sliver |
| **SliverAppBar** | AppBar 外观参数 + `pinned`、`floating`、`snap`、`expandedHeight` | 可滚动折叠的 AppBar；title/leading/flexibleSpace 为单元素 slot，actions 为数组 slot |
| **SliverPadding** / **SliverToBoxAdapter** | `padding` / `child` | sliver 与盒子世界的互转与填充 |
| **SliverFillRemaining** | `child`、`hasScrollBody`（缺省 true）、`fillOverscroll`（缺省 false） | 填满视口剩余高度的 sliver |
| **SliverPersistentHeader** | `delegate`（JS 类，`build` 布局阶段回传）、`pinned`、`floating` | 滚动折叠 / 浮出的持久化头部 |
| **SliverOpacity** / **SliverOffstage** / **SliverSafeArea** / **SliverIgnorePointer** / **SliverVisibility** | 与对应盒子版属性一致 | sliver 版可见性 / 安全区 / 拦截包装 |
| **Transform** | `offset`、`child` | 仅支持 `Transform.translate(offset: Offset(dx, dy))`；不支持 `Container.transform` 属性与 rotate/scale 工厂 |
| **EasyRefresh** | `child`、`onRefresh`、`onLoad`、`refreshOnStart`、`controller` | 三方包 `easy_refresh` 的下拉刷新 / 上拉加载容器。`child` 为被包裹的滚动视图（按原名进 `children` 的单元素 slot）；`onRefresh`/`onLoad` 是**可等待事件**（宿主触发 JS 方法、等其 Future 完成后才收起指示器，见 `capabilities/easy_refresh/`）；`controller` 为 JS `EasyRefreshController` 时走 id-bridge（`callRefresh` / `callLoad` / `finishRefresh` / `finishLoad` / `open*Secondary` / `resetHeader` 等，与 ScrollController 同一套句柄层）；指示器样式（header/footer）不参与翻译，统一用包内默认 Classic |

### 1.7 响应式

| 组件 | 支持属性 | 说明 / 限制 |
|---|---|---|
| **ListenableBuilder** | `listenable`、`builder` | `listenable` 需为模型状态字段（如 `_model`，ChangeNotifier 子类）；`builder` 闭包返回的子树抽为组件方法，运行时做「仅此节点」局部重建（不全量 setState） |
| **ValueListenableBuilder** | `valueListenable`、`builder` | `valueListenable` 需为 `ValueNotifier` 状态字段；闭包形参 `(context, value)` 注册为局部变量，子树原样引用 |
| **TweenAnimationBuilder** | `tween`、`duration`、`curve`、`builder`、`child`、`onEnd` | 隐式动画：首帧不播、直接显示 `tween.begin`；`tween.end` 变化时从**当前值**续到新目标（中途改目标不跳变），每帧按 `curve` 弯曲后 `tween.lerp` 求值，仅重建本结点子树；`onEnd` 到目标时回调一次。回调需写成方法 tear-off（`onEnd: _onEnd`） |
| **Builder** | `builder` | 多一层 context 作用域，闭包内 `context.watch<T>()` / `context.read<T>()` 可用（调用面与 Dart 完全一致） |
| **ChangeNotifierProvider** | `create`、`child`（或 `.value(value:, child:)`） | provider 包（产物落 `patch/provider.js`）；需类型参数 `ChangeNotifierProvider<MyModel>`；`create` 为模型类引用（provider 持有生命周期）或状态字段实例（归调用方）；`.value` 复用既有实例不释放 |
| **MultiProvider** | `providers`、`child` | `providers` 为 `ChangeNotifierProvider` 列表（条目需类型参数，保持平级数组；运行时登记进 provider 栈，Consumer 按最近取值） |
| **Consumer** | `builder` | 需类型参数 `Consumer<MyModel>`；闭包形参 `(context, value[, child])`，value 注册为局部变量；模型变更时局部重建 |

### 1.8 自定义组件（嵌套 / 第三方）

| 场景 | 行为 |
|---|---|
| `@PatchEntry` 组件内部使用**其他注解组件** | 生成 JS import + 运行时递归加载（元素 type 用组件类引用 + import 相对路径） |
| `@PatchEntry` 组件 build 内使用**私有组件**（`_LabeledDivider` 等） | 依赖分析自动纳入翻译，生成 JS |
| 非注解组件（如业务注入的 `LabeledDivider`） | 运行时经全局 `registerNativeComponent` 注册的原生实现渲染，或由 JS 侧 import 覆盖（JS 优先） |
| 未注册组件（宿主无 renderer） | 产物**保留其具体类型名**做元素 type（不降级为统一的 `Component`）：运行时 `JsWidgetRegistry.lookup` 未命中 → 默认 builder（按类型名找 `registerNativeComponent` 注入的原生实现，否则可见占位）。因此后续为该类型补上宿主 renderer 时，**同一份产物无需重新生成、协议不变**（生成器侧无需改动）。`registerNativeComponent` 的回调收到完整 `JsRenderContext`（`props` + `children` slot + `invoke`），可渲染子组件并回传事件 |

## 2. 样式协议（JSON 属性详解）

### 2.1 TextStyle（`Text.style`、`ButtonStyle.textStyle`、`AppBar.titleTextStyle`、`Chip.labelStyle`）

| `color` / `backgroundColor` / `decorationColor` | 见 §2.3 颜色协议 |

## 4. 事件协议

## 5. 通用翻译能力（build 内）

- **状态字段**：`_count` 类字段直接引用（`this._count`），属性一一对应
- **方法**：组件方法一比一翻译为 JS 方法
- **控制流**：`if`、`for`（含 `List.generate` 等价展开）、三目运算符
- **局部变量**：`build()` 内 `var x = ...;` 在 return 前声明（如 `var isAdult = user.age > 18;`），JS 侧同样先声明再 return
- **局部 widget 变量**：`Text text = Text();`、`final items = <Widget>[...]`、`final w = cond ? A() : B()` 按元素翻译（`var text = new Text({...})`）；字段初始化器同样支持。判据是**排除法**：只排除已知模型类与值对象 / 结构化样式，其余类构造一律按元素翻译（不再维护 widget 白名单）
- **模型类**：lib 下 model（如 `User`）经依赖调用链分析自动纳入翻译（未被引用的模型不翻译）；产物 `import` + `export class`，跨文件复用
- **生命周期**：`initState` / `dispose` 等若在组件内实现，运行时在 JS 组件对应生命周期调用

## 6. 已知限制（后续补齐方向）

1. **数字属性**在普通 props 中支持字面量、状态字段与二元运算；样式转换器内部的数值仍以字面量为主，超出范围的写法会被丢弃（见 §3.4）
2. **废弃 API 一律不支持**（技术调研只做新 API）：如 `Text.textScaleFactor`（用 `TextScaler`）、`MaterialStatePropertyAll`（用 `WidgetStatePropertyAll`）；未来 Flutter 废弃的 API 同样不再投入支持
3. **Button child** 为任意 widget（slot），图标+文字组合（`Row(Icon, Text)`）可直接使用
4. **Image** 支持 asset/network 静态路径，不支持 `Image.memory` / 动态字节
5. **事件**支持方法引用、箭头闭包与块体闭包（含 `setState`），统一为构建期箭头闭包；事件表达式里的控制流按 build 内同一套语句翻译处理
6. **命令式 API 不做**：`showDialog` / `AlertDialog` / `SnackBar` 等命令式弹出不走声明式产物协议
7. **暂不支持**：`RadioGroup`（Flutter 3.32+ 成组 API；旧 `Radio` 仍可用）、`Container.transform` 属性（用 `Transform.translate` 代替）、`Transform.rotate/scale` 工厂
8. **Positioned 其它工厂**：`Positioned.directional`（需 textDirection）、`Positioned.fromRect` / `fromRelativeRect`（需 Rect 翻译）暂不支持
9. **组件清单会持续扩充**：新增组件 = 运行时加 Renderer（能力域独立文件，核心翻译/渲染代码零改动）；翻译路径本身无需 per-widget 代码，生成器的宿主类型清单由构建期扫描宿主 `js_ui/**` 的 `r.register` 自动抽取，产物形态不同时才调整 `builderFormTypes`。
10. **PageController 外部 controller**：已支持字段初始化与内联构造；`PageController` 纳入 `jsRuntimeClassNames`，与 ScrollController / TabController / EasyRefreshController 共用同一套代理类构造翻译（见 §1.5 PageView）。
11. **跨包 import 解析**：已支持。`package:foo/x.dart` 经 `.dart_tool/package_config.json` 解析为真实文件；**本地包**（path 依赖 / workspace 成员）参与跨包翻译，其被项目组件引用到的类聚合产出为 `patch/<package>.js`；三方宿主包与框架包只用于构造签名抽取，仍走宿主注入 / 原生占位。`export` 转发（barrel）递归展开。未覆盖：本地依赖包里的顶层常量与静态单例类产物（构建期出声）。详见 `TODO.md`「2.1 跨包 import 解析」。
12. **异常控制流**：`try/catch/finally`、`throw`、`assert` 已支持基础翻译；`assert` 在产物中保持 `assert(cond, msg)` 原样调用，函数本体由运行时注入（debug 门控），不做语义改写。`catch` 的 `on Type` 过滤暂按 catch-all 近似处理，多个 catch 子句只翻译第一个（均有构建期告警）。局部函数、pattern 变量声明、label 语句仍未支持（构建期告警后跳过）。
13. **`TextStyle(color: ...)` 的取值限制**：只支持 `Colors.x` / `Colors.x.shadeN` / `Color(0x...)` / 顶层常量颜色表索引（如 `_palette[i % _palette.length]`）/ 三目 / 跨文件静态单例。**局部变量或其它任意表达式会被丢弃**（当前无构建期告警，属已知缺口；需要时把调色板提到顶层常量）。

## 7. JS 引擎能力基线

热更产物跑在 `flutter_js`（^0.8.7）接入的 JS 引擎里：iOS 侧为 JavaScriptCore、Android 侧为 QuickJS。写补丁代码 / 评估某个 Dart 写法能否翻译时，以本节为基线。

### 7.1 语法面

| 层 | 语法基线 | 说明 |
|---|---|---|
| 生成器产物 | `class`（含 `get` 访问器）、`import` / `export`、`async` / `await` | 即 ES2015 module + ES2017 async 子集；产物由生成器统一产出，手写补丁对齐同一形态 |
| JS 运行时本体（`runtime_source.dart`） | ES5（`var` / `function`，无箭头函数、无 class） | 运行时按最保守语法书写，保证任何引擎版本可 eval |

### 7.2 内建 API 补齐（`runtime_source.dart`【1c】节）

产物里调用的方法名在原生 JS 对应类型上不存在时，一律在运行时给**内建原型**补同名同义方法（项目规则：禁止在生成器按方法名映射、禁止改 Dart 单源绕开——生成器不带类型解析，同名方法必撞车，如 `clear` 既是 `List.clear()` 也是 `TextEditingController.clear()`）。

| 已补项 | 语义 |
|---|---|
| `Array.prototype.clear()` | Dart `List.clear()` 的原地清空（保持数组实例，`final` 列表也能清；返回 void） |
| `Array.prototype.first` / `last` / `isEmpty` / `isNotEmpty` / `reversed` | getter；与 Dart List / Iterable 同名同义（`reversed` 返回反转副本） |
| `Array.prototype.where` / `toList` / `add` / `removeAt` / `insert` | Dart List 同名方法；`where` 返回即时数组、`toList` 保持数组实例、`add` / `insert` 原地修改、`removeAt` 返回被删元素 |
| `String.prototype.isEmpty` / `isNotEmpty` / `compareTo` | Dart String 同名语义 |
| `Number.prototype.round` / `floor` / `ceil` / `abs` / `truncate` / `toInt` / `toDouble` / `toStringAsFixed` / `clamp` / `compareTo` | Dart `num` 同名方法 |

新增补齐项三条硬要求：①挂最具体的内建原型（禁止 `Object.prototype`）；②`Object.defineProperty` 且 `enumerable: false`（不污染 `for...in` / `Object.keys` / `JSON.stringify`）；③带存在性守卫（引擎自带时以自带为准、可重复注入）。

**已知缺口**：Dart `Map` 字面量在 JS 侧是普通对象（非 Map 实例），`Map.clear()` 无处可挂，需要时得按「字段类型是 Map」在翻译层分发；Dart `Set` 字面量翻成 `new Set([...])`，JS Set 自带 `clear()`，无需处理。

> 注意：`runtime_source.dart` 属运行时 Dart 代码，改动随 App 一起注入——热更 / 热重启不生效，必须完全重启 App。

## 8. 懒容器与更新语义（实现约定）

> 这一节的约束对**组件作者**生效：违反其中任何一条，都会表现为「滚动时 item 不刷新 / 白屏 / 每次都全量重建」。
> 运行时代码发布后不可修改，所以「要不要懒」只在构建期决定，运行时只消费协议。

### 8.1 是否懒：构建期配置，运行时零类型知识

- **唯一事实源**：`packages/hot_patch_generator/lib/src/builders/shared/js_widget_defs.dart` 的 `lazyChildHostTypes`。
- 生成器把它写进 `flutter.js`（`__lazyChildrenOf`），`__h` 给元素打 `lazyChildren: true`；运行时只认这个元素标记。
- 新增 / 调整懒容器（含三方组件）＝ 改这一处配置 + 重出产物，**运行时代码零改动**。
- 只有「子项尺寸由容器强制、不由内容决定」的容器才能懒：`PageView` / `TabBarView` / `GridView` / `SliverGrid` / `SliverFixedExtentList` / `SliverFillViewport` / 带 `itemExtent` 的 `ListView`。
- **不要**把按内容量尺寸的容器加进去（无 `itemExtent` 的 `ListView`、`SliverList`、`ReorderableListView`、`Column`）：零尺寸占位会让视口把所有 item 判为可见，懒加载反而失效。

**运行时↔产物冻结协议**（发布后不可改）：`el.lazyChildren`；`children.__builder` / `children.__items` / `children.delegate`；占位结点 props 的 `__lazy` / `__lazyFn` / `__lazyOffFn` / `__keepAlive`；占位结点的 `child` slot。新增懒容器只要沿用这套协议即可。

### 8.2 懒槽位生命周期：与宿主 element 同寿

- 宿主 **inflate** → `lazyMount`（构造 + `initState` + build）；宿主 **dispose**（滚出缓存 / 切走 Tab / 整页退出）→ `lazyUnmount`（`deactivate` → `dispose`）。
- 因此：滚出缓存的 item **State 会被销毁**，滚回来是**新实例**（`initState` 重跑）。与 Flutter 原生一致。
- 实现要求：
  - 不要假设 item 的 State 长期存活；跨滚动保留的数据放**父组件 / 模型层**，不要放 item State；
  - item 里创建的控制器 / Key 句柄归该 item 实例所有，随卸载释放，**不要跨 item 共享**；
  - 懒容器动态切态（例如 `itemExtent` 条件性出现）会重建子项，状态同理不要放在 item 内。

**保活（wantKeepAlive）**：懒槽位子树里任意组件声明 `wantKeepAlive => true`（Dart 侧的 `AutomaticKeepAliveClientMixin`）时，JS 侧在**挂载、父级重建、组件自身重建（setState）**后都会把声明经占位结点 props 的 `__keepAlive` 下发给宿主；宿主 `_JsNode` 据此注册 Flutter 真实的 `KeepAlive`（`AutomaticKeepAliveClientMixin`），切走 Tab 时 element 不再销毁，也就不会回调 `lazyUnmount` —— JS 侧 State（含已加载数据）原样保留，切回来不重跑 `initState`。
- 与 Flutter 一致：只看子树中是否有组件声明（通知冒泡语义），**不越过嵌套懒槽位**——内层 item 的保活只作用于它自己的槽位，不会把整页保活。
- Dart 侧仍需遵守 `AutomaticKeepAliveClientMixin` 的契约（`build` 里调用 `super.build(context)`）；声明为常量 `true` 时省略也不会错，但动态取值时必须调用。
- 不要用保活来替代「数据放模型层」：保活只是延长生命周期，被 `lazyUnmount`（整页退出等）时仍会正常 `dispose`。

### 8.3 父级重建：已挂载项照常 `didUpdateWidget`（与原生一致）

- 父级每次重建（包括滚动时 `setState` 更新 offset）时，懒槽位会重新执行 `itemBuilder`，并把产出的新元素 patch 到**已挂载**子树上：组件照常 `didUpdateWidget(oldWidget)` → `build`。
- 这与 Flutter 原生完全一致：`SliverChildBuilderDelegate.shouldRebuild` 恒为 `true`，父级 `setState` 会重建已挂载项；即使字段值没变，`didUpdateWidget` 也会被调用。
- **不要**按「props 值相等就跳过 patch」：它会吞掉 `didUpdateWidget` 里的副作用（计数、状态迁移等），使热更侧与原生态表现不一致。
- 唯一的例外是**元素引用相同**：生成的 `const X(...)` 按站点复用同一实例（`__const` 缓存），运行时因此按 `el === oldInst.__el` 短路——这与原生 `Element.updateChild` 的 `child.widget == newWidget` 完全一致（Dart 的 const 规范化）。父级每次重建产出的都是**新元素**（包括 builder 每次新构造的 item），照常 `didUpdateWidget`。
- 高频重建的范围由 8.2 的懒槽位生命周期兜底：只有宿主真正 inflate 的项（视口 + cacheExtent）参与 patch，离屏项已被 `lazyUnmount` 摘掉。
- **setState 按帧合并**：JS 的 `setState` 只标脏，宿主在每帧 begin frame 调 `__jsui.flushPending()` 统一重建——同一帧内来多少次 `setState`（如滚动通知逐条回传）都只 build 一次，与 Flutter 的调度粒度一致。因此 `didUpdateWidget` 的次数 ≈ 帧数，而不是通知数；UI 更新在下一帧生效（与原生一致），不要在 `setState` 之后同步依赖宿主侧的布局结果。

### 8.4 组件实现约束（踩坑清单）

1. **item 的 State 生命周期 = Flutter element 生命周期**：滚出缓存会 `dispose`，滚回来是新实例、`initState` 重跑；跨滚动保留的数据放**父组件 / 模型层**。
2. **`didUpdateWidget` 按原生频率调用**（父级每次重建都会触发），不要在里面做重活；需要节流的逻辑自行按值判断。
3. **`build` 的产出必须完整反映影响渲染的状态**，不要依赖「重建次数」或未体现为 props 的外部可变状态。
4. **props 里不要放每次新建的不可比对象**（随机 id / 时间戳 / 裸函数实例 / `new Object()`），否则每次重建都会真实下发 props；也不要把运行时簿记字段塞进 props。
5. **需要强制刷新时，把变化体现在产出里**（如 `salt` / `version` 字段）。

### 8.5 验证方法（示例 App）

入口：`常用组件 · 列表 → ListView / SingleChildScrollView`。`ListView.builder` 的 item 文本带 `uN`（本实例被父级更新的次数），颜色只由 `index + salt`（真实数据）决定。

- **滚动**：两侧颜色都不变；两侧 `uN` 同步递增（已挂载项每帧 `didUpdateWidget`，JS 侧按帧合并 setState），JS 日志（`[hot_patch] [js-log]` 前缀）会出现 `didUpdateWidget- i -N`，数量与原生同量级；
- **新进入缓存的 item**：两侧各一次 `initState`；滚出缓存再滚回：两侧都是新实例、`initState` 重跑、`uN` 从 0 开始；
- **点「列表换色（真实更新）」**：两侧同时换色。
