# flutter_hot 使用手册

从零把「注解组件 → JS 热更」接入到自己的 Flutter App，并完成本地联调。

整体模型一句话：**组件本体不做任何改造**，构建期由生成器把它静态翻译成同名 JS 模块；
线上出问题时，运行时把该组件切换到 JS 版本加载，逻辑跑在 JS 侧、渲染仍在原生 Flutter 侧。

## 1. 接入四步

### 1.1 加依赖

业务 App 的 `pubspec.yaml`（本仓库使用 pub workspace，成员包在根 `pubspec.yaml` 的
`workspace:` 列表中声明，并写 `resolution: workspace`）：

```yaml
dependencies:
  hot_patch_annotations: ^0.1.5   # 注解
  hot_patch: ^0.2.1               # 运行时

dev_dependencies:
  hot_patch_generator: ^0.2.2     # 构建期翻译（dev 依赖，不进包体）
  build_runner: ^2.4.13
```

```bash
# 仓库根一次性安装全部依赖
flutter pub get
```

### 1.2 给组件打注解

```dart
import 'package:flutter/material.dart';
import 'package:hot_patch_annotations/hot_patch_annotations.dart';

@PatchEntry('Counter')            // name 可省略，缺省取类名
class Counter extends StatefulWidget {
  const Counter({super.key});

  @override
  State<Counter> createState() => _CounterState();
}

class _CounterState extends State<Counter> {
  int _count = 0;                                  // 非 static 字段 → JS 状态
  void _inc() => setState(() => _count++);          // 方法 → JS 方法

  @override
  Widget build(BuildContext context) => Column(
        children: [
          Text('count = $_count'),
          ElevatedButton(onPressed: _inc, child: const Text('+1')),
        ],
      );
}
```

这个类仍是**完全正常的 StatefulWidget**，在被引用处照常原生渲染；热更时才走 JS 版本。

### 1.3 生成产物

```bash
dart run build_runner build --delete-conflicting-outputs
```

产物落在 `patch/`，与 `lib/` 源码路径一一对应（详见 [3. 构建配置](#3-构建配置)）。

### 1.4 声明资源并加载

Flutter 的**目录 asset 声明不递归**，需在 `pubspec.yaml` 的 `assets:` 里逐目录/逐文件声明
产物路径：

```yaml
flutter:
  assets:
    - patch/components/
    - patch/flutter.js
```

然后在业务代码里把该组件切到 JS 版本渲染（组件名与入口都走 query 参数，asset 场景组件名同样必填）：

```dart
JsUiWidget(
  // 剥离 query 后按 asset 路径加载，`component` 即 @PatchEntry 的组件名
  jsAsset: 'assets/patch/components/counter.js?component=Counter',
)
```

`jsAsset` 也支持 `http(s)://...zip` 网络补丁（见 [4. 运行时接入](#4-运行时接入)）。

## 2. 注解速查

| 注解 | 位置 | 作用 |
|---|---|---|
| `@PatchEntry()` / `@PatchEntry(name)` | 类 | 标记类为可动态下发的 UI 组件；`name` 省略时取类名 |
| `@PatchIgnore()` | 类 | 该组件不参与连带翻译，热更时始终用原生实现渲染 |
| `@HostInjected()` | 静态方法 | 声明一个 JS 可调用的宿主方法，生成器自动收集并注册 |

`@PatchEntry` 的收集口径是**整个 widget，不做字段/方法级标注**：

- 非 static 字段 → JS 状态（`_count` → JS 属性）
- 方法（除 `build` / 生命周期）→ JS 事件方法，构建期以绑定方式锚定
- `build()` → JS 渲染入口
- SnackBar 形式的方法 → 自动识别为原生通道

`@PatchIgnore` 适用场景：组件逻辑复杂或含原生依赖，不适合翻译成 JS。此时 build 树里
引用它的位置保留**具体类型名**的结点（不降级成统一的 `Component` 占位），运行时由
业务方注册的原生实现渲染：

```dart
// main() 里全局注册一次（进程内共用一张表，不要放进 build()）
// 回调参数是 JsRenderContext：props / children slot / invoke 都可用。
registerNativeComponent('_LabeledDivider', (c) => LabeledDivider(
  text: c.str('text') ?? '',
  child: c.children['child'] as Widget?,
));
```

自定义的**非 Widget 数据载体**（例如自己的导航项 / 下拉项类型）用
`registerJsDataCarrierType('MyNavItem')` 登记一次，父 renderer 就能像
`BottomNavigationBarItem` 一样直接读取它的 props/children 组装，而不会把它当
Widget 挂载。

`@HostInjected` 示例：

```dart
@HostInjected()
static String greet(String name) => 'Hi, $name';
```

生成器会产出注册清单（示例见 `example/lib/generated/host_methods.dart`），`main()` 里
调一次即可，无需手写每条通道：

```dart
void main() {
  registerHostMethods();
  runApp(const MyApp());
}
```

## 3. 构建配置

### 3.1 产物布局

| 源码 | 产物 | 说明 |
|---|---|---|
| `lib/components/counter.dart` | `patch/components/counter.js` | 含 `@PatchEntry` 的组件产物 |
| `lib/model/user.dart` | `patch/model/user.js` | 普通类 / 静态单例（`export class` / `export const`） |
| （包根伪资产 `$package$`） | `patch/flutter.js`、`patch/provider.js` | package 模块：共享结点工厂 `__h` + JS 逻辑组件 / builder 代理类，每个 package 一个文件（宿主 widget 没有工厂，元素 type 就是类型名字符串） |
| （包根伪资产 `$package$`） | `patch/manifest.json` | 清单：基本信息 + 打包时间 + 各 JS 资源内容 hash |

分流按**文件内容 + 引用可达性**判断（与目录无关）：含 `@PatchEntry` 的文件是根文件，产出这些
组件；否则只有**真的被可达类引用到**的类才产出（模型 / 单例产物）；只有顶层常量的文件产出常量；
既不可达也未被引用的文件不产出。`patch/flutter.js` 定义共享结点工厂 `__h`，宿主 widget 没有 JS
工厂（产物保留具体类型名，由宿主注册表映射），其它模块统一从 `flutter.js` `import { __h }`。
package 级模块与清单挂在包根伪资产 `$package$` 下，输入是整包、输出路径静态，**使用方无需种子
文件、无需任何配置**。

### 3.2 build.yaml 选项

`ui_widget`（package 模块）与 `patch_entry`（组件/模型产物）不读任何 options。其余两个
builder 的选项均为可选、缺省即开箱可用：

```yaml
targets:
  $default:
    builders:
      # 宿主注入注册清单（lib/generated/host_methods.dart）的目标运行时；
      # 默认指向 package:hot_patch/hot_patch.dart 的
      # JsRuntimeManager.registerHostMethod，仅换运行时实现时才需覆盖。
      hot_patch_generator:ui_host_register:
        options:
          register_import: "package:<runtime>/<runtime>.dart"
          register_call: "<Runtime>.registerHostMethod"
      # patch/manifest.json 的基本信息；缺省取包名 / 省略版本。
      hot_patch_generator:ui_patch_manifest:
        options:
          name: my_app
          version: 1.2.3
```

### 3.3 翻译约束

产物必须与 Dart 源码**一比一对应**：遇到不认识的写法是补翻译分支，而不是改 Dart 写法、
不在业务里加临时字段绕过、产物 JS 永不手改。默认值与 Flutter 保持一致（nullable 属性缺省
保持 `null`）。完整红线见[项目架构文档](项目架构文档.md)第 4 节。

## 4. 运行时接入

### 4.1 JsUiWidget 参数

| 参数 | 说明 |
|---|---|
| `jsAsset` | 补丁入口 JS（asset 路径或 `http(s)://...zip`），**必填** |
| `props` | 传给组件构造的 props，如 `{title: 'xxx'}` |
| `showBuildTime` | 调试开关：右上角角标显示补丁打包时间（取自 `manifest.json` 的 `buildTime`），不参与命中测试 |

补丁源三种形态：

- `assets/patch/...js`：随包资源；
- `http(s)://host/xxx.zip?component=Name&entry=path/to.js`：网络补丁包，下载解压后与 asset
  走同一加载逻辑；`component` 必填（入口模块里注册的组件类名），`entry` 可选（zip 内入口
  `.js` 相对路径，不传则按 `component` 反查）；
- 同一 JS 运行时里其它已加载模块。

运行时是**全局单例**（`JsRuntimeManager.instance`，所有实例共用一个 JS 引擎），不从外部注入。
每个 `JsUiWidget` 实例按内部 `pageKey` 在该运行时里隔离自己的根（结点树 / 作用域 / 订阅 /
脏队列），同屏多实例互不影响。

### 4.2 宿主方法通道

JS 侧唯一出口是 `_app_host_.invoke(channel, args)`（返回 Promise，可 `await`）；宿主侧唯一
入口是 `JsRuntimeManager.registerHostMethod(channel, impl)`。通道未注册也会回填 `null`
收尾，不留悬空 Promise。框架内建通道（`log` / `nativeToast` / `jsuiCommit`）在 `JsUiWidget`
启动时自动注册，业务只需注册自己的 `@HostInjected` 方法。

```dart
// 或手动注册任意通道
JsRuntimeManager.registerHostMethod('myChannel', (String a) => ...);
```

`JsRuntimeManager.navigatorKey` 需在 `MaterialApp.navigatorKey` 传入：热更包全局级服务
（toast / 路由推页）靠它定位 `Navigator` 与 `ScaffoldMessenger`。

### 4.3 日志与上报

包内所有日志与报错都从**唯一出口** `HotPatchLog` 流出。本地打印与上报**彼此独立**：
宿主注册一个 `sink` 即可把日志统一接到自己的日志平台。

```dart
// main()（或任意启动点）注册一次
HotPatchLog.sink = (r) => MyLogPlatform.upload(
      level: r.level.name, // debug / info / warn / error
      message: r.message,
      error: r.error,
      stack: r.stackTrace,
      time: r.time,
    );

HotPatchLog.minSinkLevel = HotPatchLevel.info; // 默认 warn：只上报「告警 + 报错」
HotPatchLog.enabled = false;                   // 只关本地打印，不影响上报
```

一条记录即一个 `HotPatchLogRecord`（`level` / `message` / `time` / `error` /
`stackTrace`）；序列化成什么协议、带哪些业务上下文，完全由宿主的 sink 决定，包内不做
任何平台约定。

#### 级别

| 级别 | 用途 | 典型来源 |
|---|---|---|
| `error` | 功能已失败 | 补丁加载失败（HTTP 非 200 / 坏 zip / 入口缺失）、JS 求值与模块求值失败、宿主方法调用失败、未注册的宿主 widget 类型 |
| `warn` | 可降级继续 | 远程包回退旧缓存、缓存损坏重下、泄漏残留、未注册通道 / op / Icons、provider 找不到提供者 |
| `info` | 链路信息（默认不上报） | 模块加载汇总、304 复用、fresh 加载 |
| `debug` | 排查细节（默认不上报） | 绑定缓存逐条 `[binding]` 明细 |

`HotPatchLog.log()` 等价于 `info`，另有 `warn` / `error` / `debug`；需要按名称**动态**
定级的调用点（如 JS console 桥）用 `HotPatchLog.emit(level, message)`。

本地打印在 `warn` / `error` 上带 `[WARN] ` / `[ERROR] ` 前缀（便于在日志里检索），
`info` / `debug` 保持原有 `[hot_patch] xxx` 格式；有异常对象时追加 ` | <error>`。

#### JS 侧日志

JS 产物里的 `console.*` 全部桥回同一出口，且**级别随之带上来**，宿主侧统一加
`[js-log] ` 前缀（如 `[hot_patch] [ERROR] [js-log] xxx`）：

| JS | 宿主级别 |
|---|---|
| `console.error` | `error` |
| `console.warn` | `warn` |
| `console.log` / `console.info` | `info` |
| `console.debug`（仅 kDebugMode 输出） | `debug` |

#### 两点注意

- `enabled` 只控制本地打印，**不影响 `sink`**：release 下（默认 `enabled = kDebugMode`
  即 false）依然能上报，而这正是日志平台的主场景；上报哪些级别由 `minSinkLevel` 决定。
- 上报是旁路：sink 自身抛异常会被兜底吞掉，不会因为上传日志打断业务。

## 5. 本地联调

示例 App 在 `example/`（业务 Dart 单源在 `example/lib/`，产物在 `example/patch/`）。

```bash
# 仓库根：杀旧服务 → build_runner 生成产物 → 打包 patch.zip → 起 http 服务
bash start_patch_server.sh

# 运行示例 App（补丁由上面的服务提供）
cd example && flutter run
```

服务详情：

- 地址 `http://127.0.0.1:8765/`，路由 `GET /patch/<相对路径>` 返回 `example/patch/` 下对应文件，
  `GET /` 列目录（调试用）；
- 日志 `/tmp/patch_server.log`；
- 示例里的补丁 URL 形如
  `http://127.0.0.1:8765/patch/patch.zip?component=HelloCard&entry=components/hello_component.js`
  （见 `example/lib/main.dart`）。

**改代码后的验证闭环**：只改 Dart 业务源码 → 重跑 `bash start_patch_server.sh` → 在 App 里重进该
页面即可看到新产物。注意 `packages/hot_patch/lib/src/js_ui/runtime_source.dart` 属运行时 Dart
代码，改动随 App 一起注入，**热重启不生效，必须完全重启 App**。

## 6. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `patch/<package>.js` 没产出 | 该包没有把 `hot_patch_generator` 加进 `dev_dependencies`（builder 只对依赖方生效）；确认依赖后再跑一次 `build_runner` |
| 运行时加载不到产物 | 目录 asset 声明不递归，需在 `assets:` 里逐目录/逐文件列出 |
| 产物里某组件结点渲染成可见占位 | 该组件被 `@PatchIgnore` 或跨库不可见（结点保留具体类型名但运行时未注册），需在 `main()` 用 `registerNativeComponent` 注册原生实现 |
| 改了 Dart 但页面没变 | patch 服务没重跑，或 App 未重进页面；改 `runtime_source.dart` 必须完全重启 App |
| 某个 Dart 写法热更后行为不对 | 先查[组件支持文档](组件支持文档.md)第 6 节「已知限制」，再确认不是产物被手改 |
| 想确认渲染/状态为何这样设计 | 见[项目架构文档](项目架构文档.md)第 1、3 节 |
